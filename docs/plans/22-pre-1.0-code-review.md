# Review Plan: 22 — Full code review before 1.0.0

A whole-codebase review before tagging 1.0.0. Not a feature: the output is
a list of findings, each fixed in its own small commit or PR, or written
down as accepted with a reason.

## Overview
Review every component once, in order of what a bug would cost on a boat:
first what switches loads and talks on the NMEA 2000 bus, last what only
affects diagnostics. Each area below lists its files, what to check, and
how to verify a finding. Findings go in the table at the end.

## Starting point (2026-09-29)
- **Dependencies are current.** Every direct dependency is on its latest
  published version: all `signalk-espos/*` at 0.12.1, `espressif/cjson`
  1.7.19~2, `espressif/w5500` 2.0.0, `espressif/led_strip` 3.0.3, NMEA2000
  at its upstream HEAD (5b7b9fc), ESP-IDF v6.0.3 (latest 6.0.x), and every
  GitHub Action on its latest release, pinned by commit.
- **Held back on purpose:**
  - ESP-IDF 6.1 is out, but every espOS 0.12.1 component requires
    `idf >=6.0.0,<6.1.0`. Move when espOS does.
  - `espressif/mdns` 1.13.1 is out; espOS pins `==1.11.3`
    (`espos_net`, `espos_n2k`). Upstream's call.
  - `esptool==4.8.1` in `release-firmware.yml` merges the release image.
    5.x is out, but espOS's own release workflow still pins 4.8.1 and the
    merge script is a copy of espOS's. Move both together.
- **Known upstream bug in the transmit path**: espOS 0.12.1's
  `TwaiNode::transmit()` hands the TWAI driver a stack frame and payload
  that are gone before a queued frame is sent (draft issue in the project
  files, `upstream/espos-n2k-twai-transmit-issue.md`). Area 1 decides
  what 1.0.0 does about it.

## How to run the review
- One area per session, in the order below. Areas 1–3 are the ones a
  release must not skip.
- Read the code against SPEC.md and the area's plan(s), not against what
  the code seems to intend.
- For each finding: severity (**blocker** for 1.0.0, **fix**, **nit**),
  file:line, a failing host test where the logic is host-testable, then
  the fix. A finding that needs the board gets a HARDWARE_TESTS.md entry.
- **Cloud** means a cloud session can do it: reading, host tests
  (`test/host/run_all.sh`, now runnable in cloud sessions since the
  Espressif hosts are reachable), and CI's firmware build. **Board** means
  it needs the Waveshare board, an NMEA 2000 bus or a SignalK server, and
  is added to HARDWARE_TESTS.md for Tobi.

## Areas, ordered by risk

### 1. NMEA 2000 transmit and PGN handling
**Files:** `components/switch_bank/src/n2k_bridge.cpp`,
`switch_bank_pgn.c`, `n2k_alerts.c`, `n2k_alert_pgn.c`,
`components/schedule/src/position_n2k.c`, `position_n2k_pgn.c`; espOS
`espos_n2k` (`twai_node.cpp`, `twai_transmitter`).
**Check:**
- The TWAI transmit lifetime bug above: can this project work around it
  (one static frame per queue slot, or tx queue depth 0 / blocking until
  sent) until espOS fixes it, or is 1.0.0 blocked on an espOS release?
- Every received PGN (127502 control, 126984 alert response, 129025/129029
  position, ISO requests): length checks before every field read,
  fast-packet reassembly limits, instance/bank-id matching, and that a
  command for a relay we don't own is ignored.
- Address claim and the stored source address (`nvs "n2k"/"addr"`):
  conflict handling, and that a lost claim stops transmitting.
- Transmit rates (127501 status, 126983/126985 alerts) against SPEC §6.2
  and canboat intervals; no burst on reconnect or config change.
- Task boundary: frames arrive on the receiver's task and are handed to
  `n2k_task`; config reaches it via `pending_cfg` under `cfg_lock`.
  Check nothing else is shared unlocked.
- Bus-off / no-bus behaviour: the relays must keep working locally.
**Verify:** Cloud: host tests for every PGN encoder/decoder with
truncated and oversized inputs (`test/host/switch_bank_pgn_test`,
`schedule_test`). Board: HARDWARE_TESTS.md section E on a busy bus
(add a "many frames queued" case for the transmit bug).

### 2. Relay fail-safe and interlocks
**Files:** `components/relay_ctrl/src/relay_ctrl.c`, `relay_hw.c`,
`tca9554.c`; `main/main.c` (`io_task`, `io_supervisor`, `start_io`,
restart and factory-reset paths).
**Check:**
- Boot state: what the TCA9554 outputs do between reset and
  `relay_ctrl_init()`, with NC/NO wiring (plan 18) and the restored mask.
- Interlocked pairs (plan 15): no path can turn both on, including
  "all on", schedules, input overrides, SignalK and N2K commands, and a
  live config change that creates a pair while both are on.
- Max on-time (plan 09), momentary/pulse relays, and SignalK-lost
  behaviour (`relay_ctrl_sk_lost`).
- Locking: `relay_ctrl_set` is called from the httpd, SignalK, NMEA 2000
  and I/O tasks; everything touched outside `s.lock` (listeners, NVS
  writes, the I2C write) is safe to run concurrently, and no listener
  can re-enter `relay_ctrl_set` under the lock.
- I2C errors: a failed expander write must not leave the reported state
  different from the real one.
- Supervisor: `io_supervisor` restart threshold, and that a stalled
  `io_task` really leads to a known relay state.
- NVS wear from persisting the relay mask on every change.
**Verify:** Cloud: `test/host/relay_ctrl_test` (add cases for every
interlock bypass found). Board: HARDWARE_TESTS.md section B, plus a
power-cycle-while-switching check.

### 3. Input overrides and alarms
**Files:** `components/input_sense/src/input_sense.c`, `input_hw.c`;
`main/main.c` (`input_override`, `on_input_change`);
`components/switch_bank/src/sk_bridge.c` (notifications),
`n2k_alerts.c`; `components/indicator/src/indicator.c` (alarm buzzer).
**Check:** debounce and toggle mode (plan 08); an override against an
interlock or max on-time; alarm raise/clear/acknowledge in SignalK and on
N2K; alarm state after a restart with the input already active; the
buzzer pattern priority between health and input alarms.
**Verify:** Cloud: `input_sense_test`, `sk_bridge_test`,
`switch_bank_pgn_test` (alerts), `indicator_test`. Board: sections C, D
and E6, and C7 for the buzzer.

### 4. Settings and persistence
**Files:** `components/device_config/src/device_config.c` and its header;
`components/counters/src/counters.c`, `counters_hw.c`;
`relay_hw.c`; `main/main.c` (`on_config_change`, `default_ota_manifest`,
`do_factory_reset`).
**Check:** range checks for every key (bank ids, channels, durations,
frequencies, schedule times); what happens to a missing, old-format or
out-of-range value after an upgrade from each earlier release;
`restart_required` keys versus keys applied live; counter flush interval
versus flash wear, and the flush on shutdown; factory reset clears
everything it should (and nothing espOS owns that it shouldn't).
**Verify:** Cloud: `device_config_test`, `counters_test` (add
out-of-range and upgrade cases). Board: an OTA from the previous release
with non-default settings keeps them (section H).

### 5. Web UI and API: auth and input validation
**Files:** `components/web_ui/src/web_ui.c`, `web_ui_logic.c`,
`www/relays.html`, `www/tones.html`; espOS `espos_httpd` auth.
**Check:** every `/api/v1/*` route is `ESPOS_HTTPD_PROTECTED` (the two
pages are public by design; confirm they carry no secrets); request body
size limits and partial `httpd_req_recv`; channel parsing
(`web_ui_parse_channel`, `_reset_channel`) for 0, 9, overflow and
trailing junk; RTTTL parsing limits in `web_ui_parse_rtttl` and
`rtttl.c`; JSON output escaping of user-set names; the single
`innerHTML` use in each page (relay and input names are user text);
CSRF on state-changing POST/PUT given espOS's auth scheme.
**Verify:** Cloud: `web_ui_test`, `tone_test` with hostile inputs.
Board: section G, plus curl without credentials against each route.

### 6. OTA and signing
**Files:** `sdkconfig.defaults` (signing), `partitions.csv`,
`main/main.c` (`default_ota_manifest`), `scripts/update_ota_manifest.py`,
`scripts/espos_merge_firmware.py`, `.github/workflows/*.yml`.
**Check:** unsigned images are refused; rollback
(`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`) marks the app valid only after
the I/O loop is healthy; manifest URL and what a tampered manifest can
do (it can only point at an image, which must still be signed); release
workflow secret handling, unsigned-release guard, mirror branch push;
partition table still matches espOS's 16 MB layout.
**Verify:** Cloud: `test/scripts` (manifest), workflow read-through, CI
build. Board: section H, including an OTA with a wrongly signed image and
a rollback after a deliberately failing boot.

### 7. WiFi and Ethernet
**Files:** `components/eth_w5500/src/eth_w5500.c`; `main/main.c`
(`do_reopen_portal`, network start); espOS `espos_net`, `espos_wifi`.
**Check:** W5500 init failure and cable unplug/replug; both interfaces up
at once; setup portal only on the BOOT button or no configured network;
socket budget (`CONFIG_LWIP_MAX_SOCKETS=16`) under a browser plus SignalK
plus OTA.
**Verify:** Cloud: read-through only (no host tests). Board: section F.

### 8. RTC and schedules
**Files:** `components/rtc_pcf85063/src/*`, `components/schedule/src/*`
(`schedule_eval.c`, `sun.c`, `position*.c`); `main/main.c`
(`schedule_tick`, `on_time_synced`).
**Check:** behaviour with no valid time (RTC lost power, no NTP); DST and
time zone; polar day/night in `sun.c`; a schedule edge missed across a
restart or a time jump; RTC write-back after SNTP; schedules versus
manual overrides and interlocks.
**Verify:** Cloud: `schedule_test`, `rtc_pcf85063_test` (add time-jump
and polar cases). Board: section B11–B13.

### 9. Memory, tasks and stack safety
**Files:** `main/main.c` (`io` task 4096, `json_to_psram`,
`start_debug_console`), `indicator.c` (task 4096),
`n2k_bridge.cpp` (task 4096), `sdkconfig.defaults`.
**Check:** stack high-water marks for `io`, `indicator`, `n2k` and
espOS's SignalK tasks under load; large locals on small stacks (the code
already moved several to static; look for more); every `malloc`/cJSON
result checked; static buffers shared between tasks; watchdog coverage
of every long-lived task; the debug console commands can't bypass
interlocks.
**Verify:** Cloud: read-through, `-fstack-usage` on the host build.
Board: `uxTaskGetStackHighWaterMark` readout after an hour of soak with
the relay page open and a busy bus; espOS health's low-RAM report.

### Areas 4, 8, 9 (reviewed 2026-09-29)
- **Checked, no finding:** schema ranges fit the struct types and buffers;
  interlock and schedule cross-key checks re-run on every save;
  `restart_required` keys are kept by their consumers until a restart; a
  missing or unparsable value degrades to the default or a disabled entry;
  counters flush every 10 min (about 6 NVS entries, negligible wear on the
  48 KB partition) and on a clean restart; RTC write-back skips its own
  source; polar day/night and midnight-spanning windows; stack frames in
  device_config, counters, schedule, rtc and web_ui_logic are all under
  320 bytes (`-fstack-usage`, host build).
- **Board, still open:** upgrade from the previous release with
  non-default settings (H); B11 including its power cut; 8.2's 25 h run;
  9.1's All on; 8.5's drift; stack high-water marks after an hour's soak.
